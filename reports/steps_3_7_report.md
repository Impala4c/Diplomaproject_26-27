## Шаг 4: новые детекторы

Добавлены GitHub, PEM, Slack и Google. Для каждого есть правила, явные заглушки, точные известные примеры и модульные проверки. Все четыре читают регулярные UTF-8 файлы независимо от расширения. AWS сохраняет прежнюю область .env и .env.*.

GitHub учитывает классические префиксы, fine-grained PAT и stateless installation token с JWT. Slack покрывает основные bot/user/app формы; неизвестная распознанная форма остаётся UNCERTAIN. Google API key получает UNCERTAIN, поскольку одного формата недостаточно для оценки его секретности и ограничений. Для PEM проверяется оболочка и содержимое base64 без криптографической валидации.

PEM-пример Figure 12 RFC 7468 исключается только при точном совпадении нормализованного тела по SHA-256 и правильной метке. Изменённый пример снова даёт предупреждение. Полноценные ключи из произвольных публичных тестов не исключаются автоматически. Папка tests, слово example и низкая предполагаемая энтропия не используются как общее разрешение.

```powershell
python -B -m unittest tests.unit.test_detectors -v
```

Ожидается 20 тестов, OK. Поддерживаемые формы, источники и границы перечислены в [README](../README.md).

## Шаг 6: интеграция

Коды завершения: 0 — нет предупреждений и покрытие полное; 1 — есть кандидаты; 2 — ошибка или неполное покрытие; 130 — прерывание. Код 2 имеет приоритет над наличием кандидатов.

SARIF 2.1.0 содержит маскированные результаты, позиции, стабильные fingerprints, commit OID и признак неполного выполнения. Форма проверена jsonschema по официальной схеме OASIS. Для полноты покрытия SARIF записывается только вместе с JSON.

.pre-commit-config.yaml проверен настоящим pre-commit 4.7.0. Во временном репозитории установленный hook заблокировал искусственный секретный коммит и принял чистый индекс. Проверены первый коммит, staged-версия при отличающейся рабочей копии, удаления, конфликты и частичный commit --only. Для последнего поддержан GIT_INDEX_FILE внутри Git-каталога; исторические сканирования от него изолированы.

.github/workflows/ci.yml проверен как YAML; команды тестов, демонстрации и сканера выполнены локально. Настроены Windows/Ubuntu, Python 3.11/3.13, fetch-depth: 0 и отдельная проверка истории. Удалённый запуск GitHub Actions не выполнялся: основной проект не опубликован и его корень не инициализирован как Git-репозиторий. Существующие hooks пользователя не изменялись.

Область hook/CI явно исключает два исходных бинарных документа: docs/planning/roadmap 1.pdf и docs/research/12-15_october_research/00_main.docx. Опция --exclude отражается в scope.excluded_path_globs и счётчике файлов вне области; обычные запуски без неё сохраняют строгий контроль пропусков. Исключения не применялись при публичных замерах. Автоматический тест проверяет, что исключение PDF не скрывает токен в соседнем текстовом файле.

При локальном сканировании копии проекта уточнён точный список искусственных PEM-заглушек для исходного учебного каталога. Составной Slack-образец в тесте теперь собирается из частей, поэтому незаконченный литерал тестового исходника не выглядит как отдельный токен. Поведение детектора на собранном тестовом значении сохранено.

Временная Git-копия текущих исходников, тестов, документации и конфигураций проверена командой сканера с --all-refs и указанными двумя исключениями: код 0, complete_for_scope: true, два NON_SECRET, предупреждений нет. Сам основной каталог и его документы не изменялись этой проверкой. Это локальная проверка будущей команды CI на одном снимке проекта, без утверждения об удалённом прогоне всей матрицы GitHub Actions.

```powershell
.\tmp\integration-tools\Scripts\python.exe -B scripts/verify_integrations.py --schema tmp/sarif-schema-2.1.0.json
```

Ожидается sarif_official_schema: OK, workflow_yaml: OK, pre_commit_installed_hook: OK, secret_commit: blocked, clean_commit: accepted. Проверка использует только свой временный каталог. В песочнице Codex запуск sh.exe для Git hook потребовал разрешения; обычные тесты запускаются в пользовательском терминале указанной общей командой.

Пакеты pre-commit, jsonschema и их зависимости установлены только в tmp/integration-tools для проверки интеграции. Runtime сканера остаётся без внешних Python-зависимостей.
