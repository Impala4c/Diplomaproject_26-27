# Поиск секретов в истории Git

Локальный сканер на правилах, версия 0.3.0. Поддерживаются AWS-пары, токены GitHub, приватные ключи PEM, токены Slack и Google API keys. Обученной ML-модели пока нет. Исходные исследовательские материалы сохранены в docs/.

Сканер читает локальные Git-объекты и не проверяет действительность credentials через сеть. Исходные значения используются в памяти; JSON, CSV, SARIF и диагностика не содержат извлечённые значения и контекст. Программа не гарантирует распознавание всех утечек.

## Запуск и проверка

Нужны Python 3.11+ и Git в PATH. Для сканера и unittest сторонние Python-пакеты не требуются. Выполняйте команды из корня проекта.

```powershell
python -B -m unittest discover -v
python -B scripts/verify_demo.py --create
```

Ожидание: 77 тестов, OK; проверка демонстрации — verification: OK, stable: true, masked: true, код 0. Команда --create создаёт временную искусственную историю внутри tmp/, проверяет её и удаляет свой временный каталог.

Чтобы сохранить отдельную демонстрацию для самостоятельного сканирования, создайте её один раз в отсутствующем каталоге:

```powershell
python -B scripts/build_synthetic_history.py tests/synthetic_histories/generated/aws_pair_demo
python -B scripts/scan_history.py tests/synthetic_histories/generated/aws_pair_demo
```

Сам сканер возвращает код 1: одна историческая AWS-пара найдена в .env, строки 2–3, в коммите добавления. В последнем снимке пары уже нет. Команда verify_demo.py без --create предназначена для исходной локальной демонстрации из сохранённого манифеста; новая история получает другие commit OID и fingerprint.

## Режимы

```powershell
python -B scripts/scan_history.py "C:\path\to\repository"
python -B scripts/scan_history.py "C:\path\to\repository" --all-refs
python -B scripts/scan_history.py "C:\path\to\repository" --snapshot --ref HEAD
python -B scripts/scan_history.py "C:\path\to\repository" --staged
python -B scripts/scan_history.py "C:\path\to\repository" --detectors aws,github
```

По умолчанию CLI включает все пять детекторов и сканирует HEAD со всеми достижимыми родительскими коммитами, включая слитые ветки. --all-refs добавляет историю всех локальных refs, включая неслитые ветки; сетевой fetch не выполняется. --snapshot читает только указанный коммит. --staged читает изменённые файлы из индекса, включая первый коммит; незакоммиченная рабочая копия не подменяет индекс. Удалённые из индекса файлы не проверяются, конфликтующий индекс даёт ошибку.

Для совместимости Python API scan_repository по умолчанию использует detectors="aws". Чтобы повторить CLI, передайте detectors="all". Требуется корень обычного Git-репозитория, worktree или bare-репозиторий. В staged-режиме учитывается временный GIT_INDEX_FILE, переданный Git hook при частичном коммите; такой индекс должен находиться внутри Git-каталога данного репозитория. Исторический режим изолирован от этой переменной.

## Отчёты

```powershell
python -B scripts/scan_history.py tests/synthetic_histories/generated/aws_pair_demo --output reports/check.json --csv reports/check.csv --sarif reports/check.sarif
```

Выбирайте новые имена: существующие файлы не перезаписываются. CSV и SARIF требуют JSON рядом, поскольку JSON содержит полные сведения о покрытии. Без --output JSON выводится в stdout. Диагностика идёт в stderr; отдельного журнала сканер не создаёт.

Сокращённый пример записи:

```json
{
  "path": ".env",
  "kind": "aws_pair",
  "line_start": 2,
  "line_end": 3,
  "status": "SUSPECTED_SECRET",
  "activity_status": "UNKNOWN",
  "components": [
    {"field": "AWS_ACCESS_KEY_ID", "line": 2, "masked_value": "[REDACTED]"},
    {"field": "AWS_SECRET_ACCESS_KEY", "line": 3, "masked_value": "[REDACTED]"}
  ],
  "absent_from_reference_snapshot": true
}
```

Полный отчёт содержит commit_oid, blob_oid, fingerprint, причины решения и coverage. Схема JSON — 2.1, SARIF — 2.1.0. NON_SECRET остаётся в JSON/CSV для анализа решений, но не включается в список предупреждений SARIF.

Fingerprint — SHA-256 канонического представления пути, коммита, строк и маскированных компонентов. Для токенов добавлена колонка, чтобы различать два появления на одной строке. Это идентификатор места находки, а не самого секретного значения. Отпечаток сохранённой AWS-демонстрации не изменился:

```text
fa6597db909e32fc4daba32e56013d1bfa8f29812ddec101133e659e69d57645
```

Если путь содержит распознанное значение, он маскируется и получает короткий хеш исходного пути для различения имён. Такой путь является меткой отчёта и может не открываться как реальный файл. Значения не попадают в открытом виде во вход fingerprint. В историческом SARIF координаты относятся к указанному коммиту; соответствующего файла может уже не быть в HEAD.

## Коды завершения

| Код | Значение |
|---|---|
| 0 | Нет предупреждений, покрытие выбранной области полное |
| 1 | Есть SUSPECTED_SECRET, UNCERTAIN или INCOMPLETE; покрытие полное |
| 2 | Ошибка аргументов, Git, записи либо неполное покрытие |
| 130 | Сканирование прервано пользователем |

Код 2 имеет приоритет над найденными кандидатами. Нулевой код не доказывает отсутствие секретов вне правил. При ошибке записи могут остаться частичные файлы отчёта.

## Детекторы и примеры

| Тип | Что проверяется | Ограничения |
|---|---|---|
| AWS | AWS_ACCESS_KEY_ID и AWS_SECRET_ACCESS_KEY в .env и .env.* одного снимка | Пара не объединяется между файлами и коммитами; временные ASIA credentials дают UNCERTAIN |
| GitHub | Семейства ghp_, gho_, ghu_, ghs_, ghr_, github_pat_; stateless ghs с JWT | Проверяется форма; checksum и действительность не проверяются |
| PEM | PRIVATE KEY, RSA, EC, DSA, ENCRYPTED и OPENSSH PRIVATE KEY | Проверяется оболочка и начало декодированного содержимого, без криптографической валидации |
| Slack | xoxb, xoxp, xapp; прочие распознанные xox-семейства сохраняются как UNCERTAIN | Webhook URL и все возможные будущие форматы не покрыты |
| Google | AIza и именованные присваивания GOOGLE_API_KEY, GOOGLE_MAPS_API_KEY, GEMINI_API_KEY | UNCERTAIN: секретность зависит от назначения и ограничений ключа |

Четыре новых детектора работают во всех регулярных UTF-8 Git-файлах, независимо от расширения. Точные известные примеры и явные заглушки дают NON_SECRET. Для AWS сохранён точный пример документации; для PEM добавлен точный пример Figure 12 RFC 7468 по хешу нормализованного тела. Полноценный ключ из произвольного публичного репозитория не считается заглушкой автоматически.

Для GitHub, Slack и Google списки известных примеров небольшие и явные. Ссылки $VAR, ${VAR} и простые GitHub Actions ${{ secrets.NAME }} распознаются как ссылки, если извлекатель поддерживает соответствующее присваивание. Имя файла example, папка tests и слово example в комментарии не исключают находку.

## Pre-commit и CI

В .pre-commit-config.yaml настроен локальный hook. После клонирования проекта установите pre-commit и hook:

```powershell
python -m pip install pre-commit
python -m pre_commit install
python -m pre_commit run secret-history
```

Hook запускает staged-сканирование всех пяти детекторов. Коды 1 и 2 блокируют коммит. Используйте Python-окружение, где установлен pre-commit; при использовании venv активируйте его перед Git-командами. Hook нужно устанавливать в каждой рабочей копии.

В hook и CI явно исключены два исходных бинарных документа: docs/planning/roadmap 1.pdf и docs/research/12-15_october_research/00_main.docx. Это видимая граница проверки: их содержимое не проверяется на секреты. Без этих аргументов обычный сканер по-прежнему сообщает о них как о пропусках и возвращает 2. --exclude можно повторять; это glob по пути относительно корня, с / и учётом регистра. Шаблоны перечисляются в scope.excluded_path_globs, число исключённых появлений входит в coverage.out_of_scope_file_occurrences. Общего исключения tests или docs нет.

Файл .github/workflows/ci.yml содержит unittest на Windows/Ubuntu и Python 3.11/3.13, проверку искусственной демонстрации и сканирование локально полученной полной истории. checkout использует fetch-depth: 0; сканирование завершает CI ошибкой при предупреждениях или неполном покрытии. В hook и CI лимит одного файла увеличен до 32 MiB для сохранённых маскированных отчётов. Публикация SARIF и артефактов не настроена. Workflow запускается при push, pull request и вручную.

Дополнительная проверка интеграций требует pre-commit, jsonschema, PyYAML и сохранённой официальной схемы SARIF:

```powershell
.\tmp\integration-tools\Scripts\python.exe -B scripts/verify_integrations.py --schema tmp/sarif-schema-2.1.0.json
```

Это окружение подготовлено в исходной локальной рабочей папке и не входит в Git. Ожидается OK для SARIF, YAML и установленного hook; искусственный секретный коммит блокируется, чистый принимается. Основной сканер от этих пакетов не зависит.

## Реальные репозитории и ограничения

С согласия пользователя локально получены bare-копии python-dotenv, aws/aws-cli и cli/cli в data/repositories/. Их код не запускался; сами копии не входят в Git и нужны для повторения замеров. Результаты и фиксированные commit OID: [итоговый отчёт](reports/steps_3_7_report.md), [замеры JSON](reports/public_benchmark_final/summary.json).

Повторить замеры в новый каталог:

```powershell
python -B scripts/benchmark_repositories.py --output reports/benchmark_repeat --large-history-commits 1000
```

Этот служебный сценарий возвращает 0 после завершения замеров; полноту сканирования нужно смотреть в coverage каждого отчёта. Для больших проектов берутся последние 1 000 элементов обратного топологического порядка rev-list, включая родителей merge. Порядок не равнозначен сортировке по дате.

Лимит файла по умолчанию — 1 MiB, меняется через --max-blob-bytes. --max-commits ограничивает число сканируемых коммитов и явно помечает усечённую историю; CLI возвращает 2. Бинарные, не-UTF-8 и большие файлы, symlink, submodule и LFS-содержимое не сканируются и отражаются как пропуски. Shallow-репозитории отклоняются. Reflog, недостижимые объекты, удалённые refs вне локальной копии и несохранённые изменения не покрываются.

Сканер не исполняет содержимое файлов, shell-подстановки и Git-фильтры. Сложный синтаксис именованных присваиваний может давать предупреждения разбора. PEM в строке с буквальными символами \\n не разворачивается в многострочный ключ. Обфускация, разбиение токенов на части, многие старые и будущие форматы могут быть пропущены. Не все публичные API keys являются секретами.

Находки в каждом коммите учитываются отдельно. Повторяющийся blob разбирается один раз, но дерево читается на каждом коммите; время, память и размер отчёта растут с историей. Проверки на трёх проектах не являются оценкой precision/recall или доказательством отсутствия утечек. ML-обучения и независимого размеченного корпуса пока нет.
