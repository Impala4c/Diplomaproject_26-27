# Исследовательские вопросы и проверяемая гипотеза

**Статус:** предлагаемые формулировки для этапа 12–15 октября. Они развивают цель roadmap и ранее обсуждённые RQ, но не считаются автоматически утверждёнными. [P0](08_sources.md#p0) [P5](08_sources.md#p5)

## RQ1. Полнота исторического извлечения

**Вопрос:** какова полнота извлечения секретов из доступной истории, в том числе секретов, отсутствующих в выбранном текущем состоянии репозитория?

**Что сравнивать:** известные положительные образцы в контролируемых историях и результаты коллектора с извлечением до ML. Затем отдельно — результаты полного конвейера. Истории добавления/удаления, начального коммита, ветки/merge, переименования, повторов и многострочного ключа предусмотрены дальнейшим roadmap. Сейчас эти тесты только перечислены как требование. [P0](08_sources.md#p0)

**Какой ответ допустим:** полнота на конкретном наборе с известными ответами; число и причины пропусков; перечень реально полученных refs и обработанных файлов. Полный recall по произвольным публичным репозиториям без полного эталона не заявляется.

**Ограничение:** «доступная история» означает достижимость из полученных ссылок, а не восстановление любой когда-либо существовавшей истории. [A02](08_sources.md#a02)

## RQ2. Влияние контекста

**Вопрос:** уменьшает ли добавление признаков контекста число ложных срабатываний по сравнению с тем же классификатором без контекста при сопоставимой полноте?

**Основное сравнение:** для одной модельной семьи использовать одинаковые разбиение, набор кандидатов и правила оценки; изменить только доступность контекстных признаков. Для Logistic Regression и Random Forest проводить такие пары отдельно. Иначе влияние контекста смешается со сменой самого классификатора. Это предлагаемое устройство эксперимента на основе roadmap. [P0](08_sources.md#p0)

**Контекст в рабочем определении:** окружающий текст кода или конфигурации, имя параметра, путь/тип файла и признаки назначения значения. Точный набор и размер текстового окна ещё не выбран; его следует зафиксировать до итогового теста. Это проектное определение, а не универсальный стандарт.

## Основная гипотеза

**H1 — проверяемое предположение из roadmap:** вариант с контекстом даёт меньше ложных срабатываний без недопустимого падения полноты. [P0](08_sources.md#p0)

Для будущего протокола предлагается формализовать операционное условие:

```text
FP_context < FP_without_context
R_context >= R_without_context - epsilon
```

`FP` — число ложных срабатываний на одном и том же оцениваемом наборе. `R` — recall. `epsilon` — допустимое абсолютное снижение recall, которое команда и руководитель должны установить до просмотра итогового test set.

**Значение epsilon в материалах не задано.** Здесь не подставлен произвольный процент. До его согласования фраза «при сопоставимой полноте» остаётся недостаточно определённой для однозначной проверки.

Пороги классификации выбираются по validation, затем фиксируются. На test только измеряется выполнение условия; подбирать порог на test до получения удобного результата нельзя. Обучение преобразований исключительно на train закреплено roadmap и соответствует рекомендациям scikit-learn. [P0](08_sources.md#p0) [A04](08_sources.md#a04)

**H0 — рабочая нулевая формулировка:** на выбранных данных нет достаточных оснований утверждать, что контекст обеспечивает требуемое уменьшение FP при согласованном ограничении по recall.

Указанное неравенство — критерий наблюдаемого эффекта, а не само по себе тест статистической значимости. Метод оценки неопределённости, объём теста и единицу независимого наблюдения предстоит определить. Нельзя назвать различие статистически значимым лишь потому, что одна цифра больше другой.

## RQ3. Качество и стоимость относительно baseline

**Вопрос:** как различаются precision, recall, F1 и время работы собственного метода и выбранных baseline на одном корпусе, по категориям секретов и для находок только в истории?

**Сравниваемые подходы по roadmap:** собственные правила без ML, Gitleaks, TruffleHog, затем ML-варианты. detect-secrets остаётся дополнительным источником подходов к аудиту, а не обязательным третьим историческим baseline. [P0](08_sources.md#p0) [S09](08_sources.md#s09)

**Условия ответа:** одинаковый доступный корпус, согласованный охват истории, независимая разметка и нормализация находок. Результат внешнего сканера не используется как окончательный эталон без разметки. [P0](08_sources.md#p0) [S03](08_sources.md#s03)

**По категориям:** показывать количество примеров вместе с метриками. Отсутствие положительных образцов категории означает отсутствие основания измерять её recall, а не доказательство идеального обнаружения. Правила неопределённых метрик описаны в `06_evaluation.md`. [A03](08_sources.md#a03)

## Допустимые исходы исследования

Контекст может помочь, не дать заметного улучшения, ухудшить полноту или давать разный эффект по категориям. Любой из этих исходов может быть корректным результатом проведённого эксперимента. Выбор вывода должен следовать данным, а не названию диплома.

Открытые параметры: `epsilon`, единица учёта, окно контекста, метод выбора порога, объём и состав теста, метод оценки неопределённости. См. `09_decisions_and_checks.md`.
