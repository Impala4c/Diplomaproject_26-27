# Обзор десяти исходных референсов

Сохранён состав `ref.md`: пять научных работ и пять официальных ресурсов/документаций. Это не десять рецензируемых научных статей. Для каждого источника отдельно указаны содержание, применение в дипломе и пределы вывода. Полные библиографические сведения, адреса и разделы — в `08_sources.md`. [P2](08_sources.md#p2)

## 1. Pathfinding.cloud [S01](08_sources.md#s01)

**Что представляет источник.** Проект посвящён AWS IAM privilege escalation и включает описания путей и самостоятельно разворачиваемые лабораторные сценарии. [S01](08_sources.md#s01)

**Как используем.** По roadmap это основа контролируемых AWS-сценариев, которые затем адаптируются к собственным Git-примерам. На этапе 12–15 октября фиксируется роль источника; выбор трёх конкретных сценариев выполняется на следующем этапе. [P0](08_sources.md#p0)

**Чего он не доказывает.** Сайт не следует описывать как размеченный набор Git-утечек или готовую методику ML-классификации строк. Наличие IAM-сценария не подтверждает утечку в каком-либо репозитории.

**Что читать:** About pathfinding.cloud и Labs / Getting Started. Прямой адрес: https://pathfinding.cloud/

## 2. How Bad Can It Git? Characterizing Secret Leakage in Public GitHub Repositories [S02](08_sources.md#s02)

**Авторы и публикация:** Michael Meli, Matthew R. McNiece, Bradley Reaves; NDSS 2019. [S02](08_sources.md#s02)

**Предмет и подход.** Исследование объединяет наблюдение публичных коммитов за период почти шести месяцев и анализ снимка репозиториев. Рассматриваются закрытые ключи и API-ключи выбранных платформ с различимыми форматами. Авторы сообщают об обнаружениях более чем в 100 000 репозиториев в своей исторической выборке. [S02](08_sources.md#s02)

**Как используем.** Это основание проблемы и пример эмпирического исследования, а не источник ожидаемого качества нашего прототипа.

**Ограничение применения.** Нельзя переносить приведённый масштаб на 2026 год, на весь GitHub или на все девять наших категорий без новых измерений.

**Что читать:** Abstract и Introduction; статья по ссылке на странице NDSS. Прямой адрес: https://www.ndss-symposium.org/ndss-paper/how-bad-can-it-git-characterizing-secret-leakage-in-public-github-repositories/

## 3. SecretBench: A Dataset of Software Secrets [S03](08_sources.md#s03)

**Авторы и публикация:** Setu Kumar Basak, Lorenzo Neil, Bradley Reaves, Laurie Williams; MSR 2023, версия arXiv:2303.06729v1. [S03](08_sources.md#s03)

**Предмет и подход.** Кандидатов извлекали Gitleaks и TruffleHog, затем размечали вручную. Описано 97 479 кандидатов из 818 репозиториев, из них 15 084 с положительной меткой. Два разметчика работали независимо и обсуждали расхождения. [S03](08_sources.md#s03)

**Как используем.** Изучаем происхождение кандидатов, процедуру разметки и метаданные мест находок. Положительная метка — не доказательство активного доступа: авторы описывают анализ значения и контекста без использования credentials. [S03](08_sources.md#s03)

**Ограничение применения.** README требует обращения к авторам и соглашения о защите данных. Доступ команды не подтверждён. Кандидаты, найденные конкретными сканерами, не гарантируют полный перечень всех секретов репозитория.

**Что читать:** Data Extraction, Steps 6–7; Ethics; README / How to Use. Прямые адреса: https://arxiv.org/abs/2303.06729v1 и https://github.com/setu1421/SecretBench

## 4. AssetHarvester: A Static Analysis Tool for Detecting Secret-Asset Pairs in Software Artifacts [S04](08_sources.md#s04)

**Авторы:** Setu Kumar Basak, K. Virgil English, Ken Ogura, Vitesh Kambara, Bradley Reaves, Laurie Williams. Использована версия arXiv:2403.19072v2; на странице указано принятие в ICSE 2025. [S04](08_sources.md#s04)

**Предмет и подход.** Инструмент ищет пары «секрет — защищаемый ресурс». Описаны pattern matching, data flow analysis и приближённые эвристики. Оценка связана с четырьмя типами баз данных. [S04](08_sources.md#s04)

**Как используем.** Работа показывает конкретный способ использовать сведения вокруг секрета и его связь с ресурсом. Для нашего проекта это аргумент исследовать контекст, но не доказательство полезности любого выбранного признака.

**Ограничение применения.** Статический анализ потоков данных не равнозначен TF-IDF. В разделе Threats to Validity авторы отмечают возможные пропуски эталонного набора. Нельзя объявлять оценку нашей системы полной лишь потому, что за основу взят известный benchmark. [S04](08_sources.md#s04)

**Что читать:** Abstract, описание метода и Threats to Validity. Прямой адрес: https://arxiv.org/abs/2403.19072v2

## 5. Detecting Hard-Coded Credentials in Software Repositories via LLMs [S05](08_sources.md#s05)

**Авторы:** Chidera Biringa, Gokhan Kul. Версия arXiv:2506.13090v1, 2025; на странице указано принятие в ACM Digital Threats: Research and Practice. [S05](08_sources.md#s05)

**Предмет и подход.** Рассматриваются векторные представления credentials с помощью BERT/GPT-2 и последующая классификация; среди оцениваемых сочетаний описан GPT2-MLP. [S05](08_sources.md#s05)

**Как используем.** В обзоре это отдельный модельный подход, с которым нужно соотнести более компактную постановку нашего прототипа.

**Ограничение применения.** Результаты другой архитектуры нельзя приписать Logistic Regression, Random Forest или TF-IDF. Контекстная обработка последовательности моделью не является автоматически тем же экспериментом, что добавление окружающих строк к нашим числовым признакам. Последнее — различение постановок, а не эмпирический результат.

**Что читать:** Approach, Evaluation, Limitations. Прямой адрес: https://arxiv.org/abs/2506.13090v1

## 6. Secret Leak Detection in Software Issue Reports using LLMs: A Comprehensive Evaluation [S06](08_sources.md#s06)

**Авторы:** Sadif Ahmed, Md Nafiu Rahman, Zahin Wahab, Gias Uddin, Rifat Shahriyar. Использована версия arXiv:2410.23657v4 от 16.04.2026; на странице указано принятие в MSR 2026. [S06](08_sources.md#s06)

**Предмет и подход.** Конвейер объединяет извлечение с помощью regex и контекстную модельную классификацию. Основной объект — GitHub issue reports. Авторы отдельно рассматривают длину контекста. [S06](08_sources.md#s06)

**Как используем.** Изучаем устройство сравнений и анализ ошибок. Сам факт существования такого конвейера исключает обоснование новизны только словами «regex плюс ИИ».

**Важная граница.** В §6.3 дополнительная оценка на 178 репозиториях тоже использует issue reports. Это не эксперимент по полному обходу Git-истории файлов. Метрики этой работы не становятся целями или результатами нашего диплома. [S06](08_sources.md#s06)

**Что читать:** Methodology, Impact of Context Window Length, §6.3. Прямой адрес: https://arxiv.org/abs/2410.23657v4

## 7. Gitleaks [S07](08_sources.md#s07)

**Тип:** официальный README инструмента. Документирован режим `git`, использующий `git log -p`, конфигурация правил и параметры отчёта. [S07](08_sources.md#s07)

**Как используем.** Основной внешний baseline по roadmap. При будущем запуске фиксируем версию, правила, параметры охвата и преобразование результатов в общую единицу учёта. [P0](08_sources.md#p0)

**Ограничения.** Patch-based обход инструмента и наш обход файловых объектов нельзя считать идентичными без функциональной проверки. Термин baseline в CLI также обозначает файл подавления ранее найденных предупреждений; это не то же самое, что сравнительный метод исследования. [S07](08_sources.md#s07)

**Актуальное примечание.** В просмотренном README есть заявление `feature complete` и ограничение будущих релизов исправлениями безопасности. Это не причина молча заменять источник: выбранный baseline нужно фиксировать по версии. [S07](08_sources.md#s07)

Прямой адрес: https://github.com/gitleaks/gitleaks

## 8. TruffleHog [S08](08_sources.md#s08)

**Тип:** официальный README инструмента. Документированы Git-источник, обнаружение credentials и отдельная функция их верификации. В CLI присутствуют `--no-verification`, `--no-update` и выбор типов результатов. [S08](08_sources.md#s08)

**Как используем.** Второй внешний baseline из roadmap, только в статическом режиме. Его срабатывания сопоставляются с независимой разметкой, а не принимаются за эталон автоматически. [P0](08_sources.md#p0)

**Ограничение.** Нельзя использовать преимущество сетевой проверки в сравнении с нашим методом, которому такая проверка запрещена. На этапе постановки подтверждена документация флагов, но не выполнен запуск выбранной версии и не измерено качество.

Прямой адрес: https://github.com/trufflesecurity/trufflehog

## 9. detect-secrets [S09](08_sources.md#s09)

**Тип:** официальный README инструмента Yelp. Описаны поиск потенциальных секретов, baseline-файл и аудит; во введении сделан акцент на новых изменениях без обхода всей Git-истории. [S09](08_sources.md#s09)

**Как используем.** Источник идей для раздельного хранения кандидатов и их ручного аудита. Дополнительное сравнение допустимо только при явно описанном режиме.

**Ограничение.** Нельзя выдавать сканирование текущего дерева за полноценный исторический baseline. Чтобы оценивать исторические версии через этот инструмент, потребовалась бы отдельная обвязка, которую наш план пока не объявляет реализованной.

Прямой адрес: https://github.com/Yelp/detect-secrets

## 10. GitHub Docs — Secret scanning [S10](08_sources.md#s10)

**Тип:** официальная документация сервиса. Описан анализ Git-истории, группы provider/generic/AI-detected patterns и отдельные validity checks. [S10](08_sources.md#s10)

**Как используем.** Проверяем терминологию и различаем поиск секретоподобного значения и проверку действительности. Документация также показывает, что исторический анализ уже является существующей возможностью, а не достаточным самостоятельным заявлением о новизне.

**Ограничение.** Список поддерживаемых шаблонов не равен нашей классификации из девяти категорий. Оповещения GitHub не используются как независимый ground truth и не заменяют локальный эксперимент.

Прямые адреса: https://docs.github.com/en/code-security/concepts/secret-security/secret-scanning и https://docs.github.com/en/code-security/reference/secret-security/supported-secret-scanning-patterns

## Вывод обзора для постановки задачи

Из рассмотренных материалов следует не обещание нового универсального детектора, а более узкая проверяемая задача: воспроизводимо сравнить варианты выбранного локального конвейера и отдельно оценить влияние контекста и исторического извлечения. Это вывод для нашего проекта на основе обзора, а не цитата из отдельной статьи.

Подборка не является систематическим обзором всей литературы и не доказывает отсутствие других аналогичных работ. Численные результаты разных статей, наборов данных и единиц учёта нельзя объединять в рейтинг нашего будущего метода.
