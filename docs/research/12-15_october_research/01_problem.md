# Постановка исследовательской задачи

**Период:** 12–15 октября 2026 года. **Команда:** два автора. **Статус:** рабочий текст для согласования, а не отчёт о выполненном эксперименте. Основание: [P0](08_sources.md#p0), [P1](08_sources.md#p1).

## 1. Тема

Разработка метода обнаружения утечек конфиденциальных данных в истории публичных Git-репозиториев на основе методов искусственного интеллекта. Формулировка сохранена из roadmap. [P0](08_sources.md#p0)

## 2. Подтверждённая исследовательская проблема

Публикация Meli, McNiece и Reaves на NDSS 2019 исследовала раскрытие секретов в публичных GitHub-репозиториях на данных коммитов и снимка репозиториев. Это эмпирическое основание для актуальности проблемы; исторические наблюдения статьи нельзя выдавать за измерения нашей команды или статистику 2026 года. [S02](08_sources.md#s02)

Секрет, убранный из последней версии файла, может сохраняться в Git-истории. Поэтому проверка только текущего состояния не равнозначна проверке исторических версий. GitHub прямо описывает сохранение hardcoded credentials в истории, а Git документирует обход достижимых объектов. [S10](08_sources.md#s10) [A02](08_sources.md#a02)

Одного совпадения с шаблоном недостаточно для независимой оценки качества обнаружения. В SecretBench кандидатов, полученных сканерами, дополнительно размечали вручную. Следовательно, результат сканера и эталонная метка должны быть различными сущностями в нашем эксперименте. Последнее предложение — методологический вывод для проекта. [S03](08_sources.md#s03)

Использование контекста и машинного обучения уже встречается в исследованиях. AssetHarvester анализирует связи «секрет — ресурс»; работы [S05](08_sources.md#s05) и [S06](08_sources.md#s06) исследуют модельные подходы к credentials и секретам в issue reports. Поэтому утверждения «контекст раньше никто не использовал» или «ИИ впервые применяется к поиску секретов» не обоснованы этой подборкой. [S04](08_sources.md#s04) [S05](08_sources.md#s05) [S06](08_sources.md#s06)

## 3. Рабочая формулировка проблемы нашего диплома

**Предлагаемая формулировка.** Требуется разработать и воспроизводимо оценить локальный метод, который извлекает кандидатов на секреты из доступной истории публичных Git-репозиториев и классифицирует их по признакам значения и окружающего контекста. Необходимо отдельно проверить полноту исторического извлечения и установить, снижает ли добавление контекста количество ложных срабатываний при заранее определённом условии сопоставимой полноты.

Это конкретизация цели roadmap, а не утверждение, что результат уже достигнут или что подобного класса методов не существует. [P0](08_sources.md#p0)

## 4. Цель, объект и предмет

**Цель по roadmap:** работающий локальный прототип «доступная Git-история → кандидаты → признаки и контекст → ML-классификация → отчёт» и проверка влияния контекста на ложные срабатывания при сопоставимой полноте. [P0](08_sources.md#p0)

**Объект — рабочая формулировка:** доступная история публичных Git-репозиториев и содержащиеся в её файловых объектах потенциально секретные строковые значения и блоки ключевого материала.

**Предмет — рабочая формулировка:** методы извлечения кандидатов и их статической контекстной ML-классификации, а также оценка полноты, ошибок обнаружения и времени работы.

Термин «конфиденциальные данные» в названии шире фактического объёма прототипа. В этом этапе предлагается явно ограничить практическую часть девятью группами секретов из материалов команды, а не обещать обнаружение любых персональных, коммерческих или медицинских данных. Это ограничение нужно согласовать с руководителем. [P0](08_sources.md#p0) [P3](08_sources.md#p3)

## 5. Задачи исследования

Задачи ниже сформулированы для будущей работы на основе этапов roadmap. Они не обозначают выполненную реализацию. [P0](08_sources.md#p0)

1. Зафиксировать определения кандидата, секретного материала, исторической находки и ложного срабатывания; описать девять категорий и случаи пересечения.
2. Подготовить источники данных и разметку с известным происхождением; отдельно учитывать собственные контролируемые истории и независимые наборы.
3. Реализовать обход доступных исторических объектов с сохранением места находки и проверить секреты, отсутствующие в выбранном текущем состоянии.
4. Подготовить собственный метод без ML и сопоставимое сравнение с Gitleaks и TruffleHog в статическом режиме.
5. Обучить предусмотренные roadmap Logistic Regression и Random Forest; сравнить варианты без контекста и с контекстом, включая проверку TF-IDF.
6. Оценить извлечение и полный конвейер по разметке; представить precision, recall, F1, ошибки, время, результаты по категориям и ограничения.

## 6. Что считать результатом обнаружения

Предлагается разделять три вывода:

**Кандидат** — фрагмент, отобранный для дальнейшей проверки. Его наличие в отчёте извлечения ещё не означает положительную эталонную метку.

**Секретный материал по разметке** — фрагмент, который в рамках документированных правил имеет назначение секрета. Политика может охватывать безопасные лабораторные образцы; их происхождение сохраняется отдельно.

**Действующие credentials** — значение, пригодность которого для доступа установлена отдельно. Наш план запрещает такую проверку на чужих сервисах, поэтому этот вывод система не делает. В прежней схеме команды статус активности обозначен `UNKNOWN`; он не превращается в `VALID` по одному совпадению или высокому баллу ML. [P0](08_sources.md#p0) [P3](08_sources.md#p3)

Старый, отозванный или тестовый ключ нельзя автоматически объявлять не-секретом только из-за предполагаемой неактивности. В проекте требуется различать роль значения и сведения о его пригодности для доступа. Это предлагаемая политика разметки, а не результат верификации.

## 7. Ожидаемый вклад и ограничения заявления о новизне

**Планируемый вклад:** реализация и оценка согласованного конвейера на зафиксированном корпусе; отдельная проверка исторического извлечения; эксперимент с включением и исключением контекста; анализ ошибок по категориям. [P0](08_sources.md#p0)

Нельзя заранее писать «разработан новый алгоритм, превосходящий существующие», «полностью решена проблема утечек» или «доказано уменьшение ложных срабатываний». Для первого утверждения нужен достаточный анализ предшествующих работ, для остальных — собственный эксперимент, которого в предоставленных материалах нет.
