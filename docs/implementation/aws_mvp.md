# Первая реализация: AWS-пара в Git-истории

Историческое описание этапов 1–2. Актуальная версия 0.3.0, новые детекторы, SARIF, pre-commit и CI описаны в [README](../../README.md). Для воспроизведения только AWS-режима ниже добавляйте `--detectors aws`.

Статус на 14 октября 2026 года: локальный прототип на правилах. Это проверка извлечения и отчётности, не обученная модель и не измерение качества на реальных утечках.

## Запуск

Нужны Python 3.11+ и Git в PATH. Сторонние Python-пакеты для сканера и тестов не нужны. Команды выполнять из корня проекта.

```powershell
python -B scripts/scan_history.py "C:\path\to\repository" --ref HEAD
```

По умолчанию JSON выводится в консоль. Для сохранения:

```powershell
python -B scripts/scan_history.py "C:\path\to\repository" --output reports/scan.json --csv reports/scan.csv
```

Выбирайте новые имена отчётов: существующие файлы не перезаписываются. Для CSV обязателен JSON, потому что только JSON содержит полные сведения о покрытии. Если Git отсутствует в PATH, задайте `--git "C:\path\to\git.exe"`. Ограничение размера одного файла задаётся через `--max-blob-bytes`, по умолчанию 1 MiB.

Коды завершения: `0` — предупреждений нет, покрытие выбранной области полное; `1` — есть подозрительные, неоднозначные или неполные кандидаты; `2` — ошибка или неполное покрытие. Код `1` в демонстрации ожидается. Даже `0` не означает отсутствие секретов вне поддерживаемой области.

## Демонстрация

```powershell
python -B scripts/build_synthetic_history.py tests/synthetic_histories/generated/aws_pair_demo
python -B scripts/scan_history.py tests/synthetic_histories/generated/aws_pair_demo --output reports/aws_pair_demo.json --csv reports/aws_pair_demo.csv
```

Скрипт создаёт новый локальный Git-репозиторий без remote: чистая конфигурация → добавление синтетической пары → удаление пары. Он печатает номера коммитов и ожидаемые места находок без значений. Идентификатор и секрет детерминированно вычисляются из тестового seed и никогда не выпускались в AWS.

Ожидается одна запись `SUSPECTED_SECRET`, строки 2–3 файла `.env`, коммит добавления в `commit_oid` и `commits`, `absent_from_reference_env: true`. На последнем коммите в `.env` остаётся `APP_ENV=development`. Генератор отказывается использовать существующую папку; повторный запуск делайте с новым именем. Папка `generated/` исключена из будущего Git основного проекта.

Два сканирования уже созданного репозитория теперь дают одинаковый fingerprint. Проверка без создания файлов:

```powershell
$first = python -B scripts/scan_history.py tests/synthetic_histories/generated/aws_pair_demo | ConvertFrom-Json
$second = python -B scripts/scan_history.py tests/synthetic_histories/generated/aws_pair_demo | ConvertFrom-Json
$first.candidates[0].fingerprint -eq $second.candidates[0].fingerprint
```

Ожидается `True`. Каждый сканер возвращает код `1`, потому что есть находка. Повторное создание истории может дать другие commit OID, поэтому стабильность проверяется на одном и том же репозитории и выбранном ref.

## Что реализовано

1. Выбранный `--ref` разрешается в фиксированный commit OID. По умолчанию используется `HEAD`, а не автоматически найденная основная ветка.
2. Читаются все предки этого коммита, включая слитые ветки. Неслитые ветки, другие refs и незакоммиченные файлы не входят в этот запуск.
3. Для каждого коммита читается дерево. Выбираются обычные файлы с именем `.env` или префиксом `.env.` в любом каталоге. Содержимое одного blob разбирается один раз, пути и появления сохраняются отдельно.
4. Извлекаются только `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY`. Поддерживаются однострочные значения, одинарные/двойные кавычки без экранирования, пробелы, `export`, конечные комментарии и закомментированные присваивания.
5. При единственном присваивании каждому полю в одной версии файла образуется предполагаемая пара. Повторные присваивания, смешение активной и закомментированной записи или ошибки разбора дают неоднозначность. Значения между файлами и коммитами не соединяются.
6. Правила присваивают статус. Все кандидаты, включая отрицательные, остаются в JSON/CSV.
7. Отчёт содержит координаты, коммит, причину, числовые признаки, полностью закрытые значения и стабильный fingerprint SHA-256. Исходный текст и свободный контекст не экспортируются.

## Правила v1

| Статус | Пример основания |
|---|---|
| `SUSPECTED_SECRET` | Литеральная пара ожидаемого формата или секретный компонент без пригодного идентификатора |
| `NON_SECRET` | Все значения пустые, явные заглушки, простые ссылки на переменные или точная публичная пара из документации AWS |
| `INCOMPLETE` | Похожий на AWS идентификатор без литерального секретного значения |
| `UNCERTAIN` | Неожиданный формат, повторные присваивания, смешанный контекст комментария или временные credentials |

Форматный фильтр первой версии: идентификатор `AKIA` + 16 заглавных латинских букв/цифр; секрет — 40 символов из латинских букв, цифр, `/`, `+`, `=`. Это эвристика, не подтверждение действительности или полноты всех исторических форматов AWS. `ASIA` помечается как временный вариант вне текущего объёма; session token ещё не извлекается.

Название `.env.example`, каталог тестов или слово `example` не исключают кандидата. Для известных учебных значений используется только точное совпадение всей пары. Такой список не переносится автоматически в будущую ML-разметку: в датасетах значения могут быть обфусцированы.

## Значение полей отчёта

- В схеме отчёта `2.0` одна запись — одно появление кандидата в конкретном коммите и пути. Поле `commit_oid` содержит полный OID, а совместимое поле `commits` — список из этого одного OID. Повторы в разных коммитах получают отдельные записи и fingerprint, хотя содержимое blob по-прежнему разбирается один раз. Число записей обозначает появления, а не число уникальных секретных значений.
- `location_in_reference_snapshot` — присутствует ли этот blob по этому пути в выбранном коммите.
- `absent_from_reference_env` — отсутствует ли та же извлечённая пара или отдельный компонент в разобранных `.env`-файлах выбранного коммита. Для отдельного компонента учитывается и его вхождение в полную пару. Для пары проверяется именно сочетание полей; это не обещание отсутствия отдельных значений во всех файлах репозитория.
- При неполном покрытии текущего снимка отсутствие кандидата записывается как `null`, а подтверждённое присутствие — как `false`.
- `activity_status: UNKNOWN` — проверка доступа не выполнялась. `status` является решением правил, а не эталонной меткой.
- `fingerprint` — SHA-256 от канонического JSON: версия схемы `location-v1`, относительный Git-путь, полный commit OID, начальная/конечная строки и компоненты с именем поля, номером строки и маской `[REDACTED]` или `[EMPTY]`. Ключи JSON сортируются, пробелы-разделители убраны, Unicode экранируется, компоненты сортируются по строке и имени поля. Исходные значения, контекст, числовые признаки и решение правил в хеш не входят.
- Одинаковое появление даёт одинаковый fingerprint в разных запусках. Изменение пути, коммита, строк или маски меняет отпечаток. Это идентификатор места находки, а не хеш секретного значения. Переписывание Git-истории с изменением OID изменит fingerprint.
- Для сравнения с текущим снимком значения сопоставляются отдельно только в памяти процесса. Изменение публичного fingerprint не меняет правило `absent_from_reference_env`; внутренние значения не экспортируются.
- В CSV путь представлен JSON-строкой, чтобы имя файла не интерпретировалось табличным редактором как формула.

## Покрытие и ограничения

Большие, бинарные, не-UTF-8 файлы, символические ссылки, LFS-указатели и submodules отражаются в `coverage.skipped`. Неподдерживаемые присваивания отмечаются в `parse_warnings`. Shallow-репозитории отвергаются. При сбое Git запуск завершается ошибкой; пустой успешный отчёт не создаётся.

Сканер не выполняет содержимое репозитория, не меняет рабочие файлы, не делает checkout, fetch или запросов к AWS. Чтение идёт через `rev-list`, `ls-tree` и `cat-file`; Git-протоколы и ленивое получение отсутствующих объектов отключены. Исходные значения существуют только в памяти процесса при обработке.

Это первая версия для небольших локальных репозиториев: дерево читается на каждом коммите, а результаты разбора кэшируются в памяти. Масштабирование, INI/JSON/YAML, произвольные имена полей, многострочный `.env`, экранирование и подстановки с операторами shell не реализованы. Связь двух полей в одном файле — предположение извлекателя, не доказательство принадлежности одному аккаунту.

## Тесты и дальнейшее подключение ML

```powershell
python -B -m unittest discover -v
```

Тесты создают временные локальные Git-репозитории в `tmp/` и удаляют только свои проверенные временные каталоги. Проверяются первоначальный коммит, удаление, повторы, переименование, ветки/merge, отрицательные примеры, неполные пары, ограничения чтения, маскировка и CLI. Сетевых данных для тестов не требуется.

Добавлены проверки стабильности fingerprint между запусками функции и отдельными процессами CLI, различия разных мест находок, сохранения старых идентификаторов после добавления коммитов и отсутствия исходных значений во входе SHA-256. Немаскированные компоненты функция fingerprint отвергает.

Извлечение (`candidates/aws.py`), признаки (`features/aws.py`), правила (`baselines/aws_rules.py`) и экспорт (`reporting/report.py`) разделены. `Candidate` содержит значения и локальный контекст в памяти. Будущая модель сможет получить признаки до фильтрации. Произвольный контекст потребуется отдельно маскировать перед подготовкой обучающих артефактов. Обучения, сохранения датасета и оценки precision/recall на независимых данных сейчас нет.

Основания форматов и операций: [AWS access keys](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_access-keys.html), [IAM identifiers](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_identifiers.html), [Git rev-list](https://git-scm.com/docs/git-rev-list), [Git ls-tree](https://git-scm.com/docs/git-ls-tree), [Git cat-file](https://git-scm.com/docs/git-cat-file).
