# Референсы для дипломной работы

**Тема:** Разработка метода обнаружения утечек конфиденциальных данных в истории публичных Git-репозиториев на основе методов искусственного интеллекта.

**Всего: 10 источников. Дата проверки ссылок: 03.10.2026.** Ранее предложенный Pathfinding.cloud включён под № 1. В подборке пять научных работ и пять официальных ресурсов/документаций; это не десять рецензируемых статей.

## [1] Pathfinding.cloud

**Автор / организация:** Datadog и участники проекта. **Тип:** каталог AWS IAM attack paths и лабораторная методология; обновляемый веб-ресурс.

Основной сайт: https://pathfinding.cloud/

Лабораторная методология: https://pathfinding.cloud/labs/getting-started/

Исходный код: https://github.com/DataDog/pathfinding.cloud

**Для диплома:** основа контролируемых AWS-сценариев и объяснения последствий раскрытия учётных данных. Выбранные сценарии адаптируются в собственные Git-репозитории с искусственными значениями и известной историей коммитов. Сам Pathfinding.cloud не является размеченным датасетом Git-утечек или методом ML-детекции. Развёртывание AWS и эксплуатация облака не входят в декабрьский прототип.

## [2] How Bad Can It Git? Characterizing Secret Leakage in Public GitHub Repositories

**Авторы:** Michael Meli, Matthew R. McNiece, Bradley Reaves. **Год:** 2019. **Публикация:** Network and Distributed System Security Symposium (NDSS).

Статья и материалы: https://www.ndss-symposium.org/ndss-paper/how-bad-can-it-git-characterizing-secret-leakage-in-public-github-repositories/

**Для диплома:** постановка проблемы раскрытия секретов в публичных репозиториях, типы секретов и исследовательский подход к их измерению. Историческая фундаментальная работа; её показатели нельзя представлять как статистику за 2026 год.

## [3] SecretBench: A Dataset of Software Secrets

**Авторы:** Setu Kumar Basak, Lorenzo Neil, Bradley Reaves, Laurie Williams. **Год:** 2023. **Публикация:** International Conference on Mining Software Repositories (MSR).

Статья: https://arxiv.org/abs/2303.06729

Исследовательский репозиторий: https://github.com/setu1421/SecretBench

**Для диплома:** размеченные примеры и методика оценки secret detection; основа для правил разметки и независимой проверки. Различать кандидатов и подтверждённые разметкой секреты. Перед включением данных проверить доступность конкретной версии и условия использования. Для проверки обхода Git-истории дополнительно нужны собственные истории коммитов.

## [4] AssetHarvester: A Static Analysis Tool for Detecting Secret-Asset Pairs in Software Artifacts

**Авторы:** Setu Kumar Basak, K. Virgil English, Ken Ogura, Vitesh Kambara, Bradley Reaves, Laurie Williams. **Год:** 2025; препринт — 2024. **Публикация:** International Conference on Software Engineering (ICSE).

Статья: https://arxiv.org/abs/2403.19072

DOI: https://doi.org/10.1109/ICSE55347.2025.00067

Исследовательский репозиторий: https://github.com/setu1421/AssetHarvester

**Для диплома:** использование контекста и связей между секретом и ресурсом, например паролем и базой данных. Помогает обосновать анализ окружающего кода. Это метод статического анализа, а не готовая нейросетевая модель.

## [5] Detecting Hard-Coded Credentials in Software Repositories via LLMs

**Авторы:** Chidera Biringa, Gokhan Kul. **Год:** 2025. **Версия:** arXiv:2506.13090; на странице указано принятие в ACM Digital Threats: Research and Practice.

Статья: https://arxiv.org/abs/2506.13090

**Для диплома:** контекстные представления кода и ML-классификация hard-coded credentials; обоснование дальнейшего расширения модели. До декабря реализуется более компактная модель с признаками и TF-IDF-контекстом, а не воспроизведение всей LLM-системы.

## [6] Secret Leak Detection in Software Issue Reports using LLMs: A Comprehensive Evaluation

**Авторы:** Sadif Ahmed, Md Nafiu Rahman, Zahin Wahab, Gias Uddin, Rifat Shahriyar. **Год используемой версии:** 2026. **Публикация:** MSR 2026; **версия:** arXiv:2410.23657v4.

Статья: https://arxiv.org/abs/2410.23657v4

Исследовательский репозиторий: https://github.com/nafiurahman00/Secret-Breach-Prevention-In-Software-Issue-Reports

**Для диплома:** сочетание извлечения кандидатов и контекстной оценки, проектирование сравнительных экспериментов. Объект статьи — issue reports, а не история коммитов; перенос выводов на Git-код необходимо проверять отдельно. Указаны название и авторы актуальной версии, а не первоначального препринта 2024 года.

## [7] Gitleaks — официальная документация и исходный код

**Автор:** Gitleaks project. **Тип:** программный инструмент, обновляемая документация.

Репозиторий и документация: https://github.com/gitleaks/gitleaks

**Для диплома:** основной внешний baseline для поиска секретов, включая Git-историю. Зафиксировать версию, конфигурацию правил и параметры запуска. Сравнивать с собственным методом на одинаковых репозиториях, коммитах и единице учёта находок.

## [8] TruffleHog — официальная документация и исходный код

**Автор / организация:** Truffle Security. **Тип:** программный инструмент, обновляемая документация.

Репозиторий и документация: https://github.com/trufflesecurity/trufflehog

**Для диплома:** второй внешний baseline с набором провайдерских детекторов. Использовать только локальное обнаружение, отключив сетевую проверку действительности найденных credentials. Не приравнивать метки инструмента к независимой ручной разметке.

## [9] detect-secrets — официальная документация и исходный код

**Автор / организация:** Yelp и участники проекта. **Тип:** программный инструмент, обновляемая документация.

Репозиторий и документация: https://github.com/Yelp/detect-secrets

**Для диплома:** плагины поиска, baseline-файлы и процедура аудита ложных срабатываний. В основном плане — дополнительное сравнение снимков файлов. Для сопоставимого анализа всей Git-истории потребуется собственная обвязка; её нельзя считать встроенной возможностью инструмента.

## [10] GitHub Docs — Secret scanning

**Автор / организация:** GitHub. **Тип:** официальная документация, обновляемый веб-ресурс.

Обзор: https://docs.github.com/en/code-security/concepts/secret-security/secret-scanning

Поддерживаемые категории и шаблоны: https://docs.github.com/en/code-security/reference/secret-security/supported-secret-scanning-patterns

**Для диплома:** классификация секретов, описание задачи обнаружения и различие между нахождением строки и проверкой её действительности. Сервис GitHub не используется как ground truth или как замена локальному воспроизводимому эксперименту.
